# UI quality bar

The owner's personal bar for anything visual. A repository's own design skill or design system
wins on specifics (tokens, components, layout); these rules sit on top of it and of any general
design skill that is installed.

## Look

- No generic look: SaaS dashboard card grids, dashboard layouts for things that are not
  dashboards, glassmorphism, decorative or purple-blue "AI" gradients, gradient blobs. (high)
- Avoid clutter and visual chaos. Every element earns its place; hierarchy before decoration.
  (high)
- Use strong color sparingly, as accents rather than fills. Never fill whole cards, panels or
  matrices with saturated color. (high)
- Never rely on color alone to carry meaning; pair it with text, shape or position. (high)
- Improve within the existing identity. Do not redesign unless asked. (high)
- Never fix overflow by shrinking fonts, margins or spacing, or by truncating meaningful content;
  restructure the layout instead. (high)

## Motion

- Smooth, calm and purposeful: each animation explains a change (where something came from,
  what changed, what is loading). Never flashy, excessive or merely decorative. (high)

## Evidence

A UI change is done only when a screenshot of the real page shows it, per the verification
rules in `AGENTS.md`.
